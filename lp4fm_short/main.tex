\begin{abstract}
Cross-language probe transfer is often interpreted as evidence that a code
model represents program semantics independently of programming language. We
test this interpretation for variable roles in Qwen2.5-Coder-1.5B using
parallel Python, JavaScript, and PHP solutions. A masked character $n$-gram
classifier loses $0.126$ macro-F1 on transfers involving Python relative to
JavaScript$\leftrightarrow$PHP. A residual-stream probe changes by only
$-0.012$ ($95\%$ problem-clustered interval $[-0.034,0.020]$), which appears
to support language-invariant role encoding. This probe mean-pools the
occurrence's own tokens, whereas the surface classifier masks the identifier.
Excluding the occurrence from the readout reduces mean transfer from $0.844$
to $0.589$ and changes the boundary effect to $-0.060$
$[-0.088,-0.030]$. The shift is $-0.048$ $[-0.088,-0.016]$. Context-matched untrained networks show boundaries of $-0.064$ and $-0.035$
across two weight initializations; under neither is the trained probe flatter.
Training-associated lift remains positive in both language groups under both
floors. Thus the original invariance is not
identified independently of the readout, while the restricted readout still
contains training-dependent role information.
\end{abstract}

\section{Introduction}

Linear probes measure whether a label is decodable from a representation. They
do not establish that the model uses the decoded feature, and their performance
can reflect probe capacity or information already available in the probe
input~\citep{hewitt2019control,voita2020mdl,ravichander2021probing,
elazar2021amnesic,belinkov2022probing}. Cross-language
transfer adds a further interpretation. If a probe fitted on one programming
language transfers to another, the decoded feature may appear independent of
surface form.

Existing work has recovered code syntax across languages with probe
baselines~\citep{hernandezlopez2026syntactic}, separated language-specific from
language-agnostic embedding components~\citep{utpala2024language}, and measured
uneven alignment among programming languages on parallel
programs~\citep{kargaran2025programming}; within-language suites map what code
models encode across many probe tasks~\citep{karmakar2021what,troshin2022probing,karmakar2024inspect}.
We do not add a task. These studies establish that code
representations contain both shared and language-specific structure. They do
not provide a model-free, feature-restricted comparator on the same
cross-language prediction task.

We add that comparator for variable roles such as accumulator and index
key~\citep{sajaniemi2002roles}. Variable roles describe what a variable does,
which makes them a plausible target for language-independent representation.
The initial probe result supports that interpretation. It changes when the
readout no longer pools the occurrence tokens that carry the identifier, which
parallel implementations often preserve~\citep{kargaran2025programming}. This
ablation localizes the instability to the readout support. It does not, by
itself, identify lexical identity as the cause because pooling support and
token position change together.

\section{Setup}

\paragraph{Corpus.}
XLCoST~\citep{zhu2022xlcost} provides parallel solutions keyed by problem
identifiers that are stable across languages. Python, JavaScript, and PHP are
the only three languages with at least $500$ shared problems for every pair.
For example, C\# and Java share only $175$ problems
(Appendix~\ref{app:overlap}). We first restrict each language to the $869$
problems present in all three. Role extraction then determines which of those
problems contain a usable occurrence for each role, so role-specific coverage
still differs across cells. Data splits use a fixed hash of the problem
identifier and never separate occurrences from the same problem.

The Python data retain formatting that the JavaScript and PHP data do not.
Because this formatting difference coincides with the language contrast, we
remove whitespace before constructing character features. Equalizing
whitespace on both sides changes each of the three audited iterator transfers
by less than $0.001$.

\paragraph{Conditions.}
We evaluate four conditions on matched language pairs.

\begin{itemize}\itemsep2pt
\item \textbf{Surface $n$-gram.} A character $n$-gram classifier over the
context around an occurrence with every instance of the variable's name
replaced by a placeholder. The classifier is fitted on the source language and
evaluated on the target. We report one fixed masked-window feature set rather
than selecting the best feature set separately for each cell.
\item \textbf{Probe, span-pooled.} Logistic regression on residual activations
mean-pooled over the occurrence's own tokens, layer chosen on source-language
validation data. This reads the identifier.
\item \textbf{Probe, occurrence-excluded.} The same, pooling the $16$ tokens either
side of the occurrence while excluding its tokens. Model inputs and weights are
unchanged. Only the readout is altered.
\item \textbf{Untrained.} The same architecture and tokenizer with randomly
initialized weights, evaluated at each pooling. Randomly initialized networks
can retain substantial lexical and structural information, so they provide a
necessary floor~\citep{zhang2018language,hewitt2019control}. Each probe is
compared with the floor using the same readout.
\end{itemize}

Models are Qwen2.5-Coder-1.5B~\citep{hui2024qwencoder} and, for the untrained
control, the corresponding Qwen2.5 architecture~\citep{qwen2024qwen25}.
Qwen2.5-Coder is continued-pretrained from the Qwen2.5 model
family~\citep{hui2024qwencoder}. Reported uncertainty resamples complete
problems rather than individual occurrences.

\section{The inferred boundary depends on readout support}

The span-pooled probe reaches $0.844$ overall. Its cross-language boundary is
$-0.012$ with a problem-clustered interval of $[-0.034,0.020]$. This is the
result that would normally be interpreted as language-independent role
decodability.

Excluding the occurrence from the readout lowers mean transfer from $0.844$ to
$0.589$ (Figure~\ref{fig:masked}). The context-matched untrained model reaches
$0.485$. The boundary changes to $-0.060$ $[-0.088,-0.030]$; the
readout-induced shift is $-0.048$ $[-0.088,-0.016]$. The original flat
boundary is therefore not robust to where activations are read.

The occurrence-excluded untrained model has a $-0.064$ boundary
$[-0.089,-0.039]$; subtracting this floor gives a trained-minus-untrained
boundary of $+0.003$ $[-0.027,0.036]$. A second weight initialization yields a
$-0.035$ floor boundary with an overall level of $0.497$ against the first
initialization's $0.485$: the floor's level is stable while its boundary varies
across initializations, and the trained boundary ($-0.060$) lies within that
variation, at its steeper end. Under neither initialization is the trained
probe flatter than the untrained network. Training still contributes:
trained-minus-untrained transfer is $+0.102$ $[0.065,0.132]$ close and
$+0.106$ $[0.081,0.127]$ for Python transfers against the first floor, and
$+0.110$ and $+0.083$ in point terms against the second.

Identifier exclusion also matters within languages. Mean in-language F1 falls
from $0.898$ to $0.771$, a reduction of $0.127$. The context-pooled untrained
model reaches $0.623$ in language. Direct access to the occurrence therefore
accounts for a substantial part of both in-language and cross-language
decodability.

The remaining occurrence-excluded margin supports training-dependent role
information in this readout. It does not establish a language-independent
mechanism because the training lift is similar on both sides of the boundary.
The surface baseline
outperforms the context-pooled probe in $14$ of $18$ matched cells with
problem-clustered intervals below zero for the paired difference. This shows
surface sufficiency on the same prediction items; it is not a decomposition of
the model signal, because the model still processes unmasked source code.

\section{Discussion}

The central result concerns measurement. A probe that pools over an occurrence
can use information concentrated at those tokens, including lexical
regularities preserved by parallel programs. A randomly initialized model
tests what training contributes under a fixed readout, not whether that
readout isolates the intended construct. Conversely, occurrence exclusion
changes the pooled positions and their information content together. Calling
the difference ``identifier leakage'' would therefore overstate what this
experiment identifies.

The model-free condition exposes a different source of evidence. Its input
withholds every target-name occurrence, while the probe model sees the original
program. The two predictors share labels and test items but not information
sets, so their comparison establishes surface sufficiency rather than an
isolated representational increment.
Model-free baselines are established in code probing
generally~\citep{troshin2022probing}, but the cited cross-language studies do not
fit one on the same prediction items
~\citep{hernandezlopez2026syntactic,utpala2024language,kargaran2025programming}.
The present result extends the usual distinction between decodability and model
use~\citep{elazar2021amnesic,belinkov2022probing}. Decodability can also arise from a
label correlate exposed directly by the readout.

\paragraph{Reconciling with prior alignment results.}
\citet{kargaran2025programming} find Python the \emph{least} aligned of these
three languages on parallel programs, whereas the span-pooled probe changes
little across transfers involving Python. The studies measure different
quantities, so agreement is not required. Nevertheless, excluding the
identifier produces a probe contrast in the direction of their alignment
result. This convergence is compatible with a genuine Python boundary, but it
does not establish a common mechanism.

\paragraph{Falsifying evidence.}
Our interpretation would weaken if a context-pooled probe developed a growing
margin over its matched floor at larger scale. It would also weaken if
same-readout input-level identifier replacement preserved the flat transfer
curve, or if a
parallel corpus without shared naming conventions produced the original
span-pooled invariance. These experiments distinguish lexical leakage,
readout choice, and genuinely shared role information.

\paragraph{Implication for linguistic medium studies.}
When linguistic or symbolic form is manipulated, the measurement instrument
must not retain a feature that the manipulation preserves. Parallel corpora
concentrate such features, including names, entities, and numbers. A
feature-restricted model-free comparator and a matched readout ablation provide
two inexpensive checks before invariance is attributed to a model
representation.

\paragraph{Limitations.}
The study uses one $1.5$B model, three languages, three roles, and a single
context width. Python supplies the only broad language contrast. Role-specific
coverage differs after extraction even though the corpus is restricted to a
common problem pool, so composition may still affect group means. Iterator
labels use different extractor families across languages and carry most of the
surface effect; no multilingual hand-audit quantifies extractor error. The occurrence-excluded control uses two random weight initializations at two
probe seeds each, whereas trained probes use five seeds; its boundary varies
across initializations ($-0.064$, $-0.035$) while its level does not ($0.485$,
$0.497$), and only the first initialization's interval estimates are computed. It removes the target occurrence from
the readout but may retain correlated nearby uses and names, and it changes
pooling support rather than intervening on lexical identity alone. No
same-readout probe under input-level identifier replacement is available.
These results concern decodability rather than model use and do not support a
causal claim about the model's computation.

\section{Reproducibility}
\label{app:repro}
Every figure is regenerated from committed result files, and a regression test
recomputes the headline values from those files. The context-pooled trained and untrained conditions and the prediction-level
boundary analysis are committed per cell; the second floor initialization's
per-cell artifacts are pending commitment from the verification run. Intervals resample stable problem identifiers once across all cells
and conditions. Activation extraction is the only accelerator-dependent step.
Probes use logistic regression on residual activations pooled over either the
occurrence or the $16$ tokens on each side. The surface baseline uses a
\texttt{char\_wb} tf-idf vectorizer with $n \in [2,4]$ and source-language
logistic regression. Store identities record model initialization and pooling
so conditions cannot be mixed silently.
