\begin{abstract}
A linear probe on a code model's residual stream recovers a variable's
\emph{role} almost as well in a language it was not fitted on as in the one it
was: across six ordered pairs of Python, JavaScript and PHP, matched problem by
problem, transfer moves $-0.012$ macro-F1 at a boundary where a model-free
character $n$-gram classifier loses $0.126$. Read at face value that says role
representations are language-independent. It is largely an artifact. The probe
pools activations over the occurrence's own tokens, so it reads the variable's name. The baseline is forbidden to. Pooling only surrounding tokens, with the
forward pass unchanged, costs the probe $65\%$ of its margin over an untrained
network of the same architecture and pooling ($+0.269 \rightarrow +0.093$) and
multiplies its boundary effect fivefold ($-0.012 \rightarrow -0.061$), leaving
it no flatter than the untrained network itself ($-0.042$). The invariance was
mostly the identifier. We report this as a caution for cross-lingual probing of
code models, together with the model-free comparator such studies have lacked.
\end{abstract}

\section{Introduction}

Probes are how we ask what a code model represents, and cross-lingual probes ask
whether what it represents is tied to the language it saw. Prior work has fitted
probes on one programming language and evaluated on
another~\citep{hernandezlopez2026syntactic}, found language-specific components
that can be removed from code embeddings~\citep{utpala2024language}, and shown
that alignment between languages on parallel programs is
uneven~\citep{kargaran2025programming}. That literature has an untrained-network
floor but no model-free one: no non-neural classifier is fitted on the same
items, so a probe's transfer curve has nothing to be read against except itself.

We supply that comparator, and it changes the reading. A \emph{variable
role}~\citep{sajaniemi2002roles}, such as accumulator or index key, is a
property of what a variable does rather than of its name or its language, so it
is a case where a language-independent representation is plausible on its face.
Fitting a role classifier on one language and testing on another, the probe
looks strikingly invariant beside a surface baseline that is not.

The comparison is unfair in a way that turns out to decide the result. The probe
pools activations over the occurrence's own tokens and therefore reads the identifier, which the surface baseline has masked out. Removing that
asymmetry removes most of the effect. What survives is a smaller
finding about the surface and a methodological caution about the probe.

\section{Setup}

\paragraph{Corpus.} XLCoST~\citep{zhu2022xlcost} provides parallel solutions
keyed by a problem identifier stable across languages. Only Python, JavaScript
and PHP share problems at usable rates. No other pair in XLCoST reaches $500$ shared
problems, including same-family pairs such as C\# and Java, which share
$175$ (Appendix~\ref{app:overlap}). We restrict all three languages to the $869$
problems all three share, so every ordered pair scores identical problem ids and
a difference between cells cannot be a difference in subject matter. Roles are
extracted per occurrence and split by a frozen hash of the problem id.

\paragraph{The four conditions.} All are scored on the same occurrences.

\begin{itemize}\itemsep2pt
\item \textbf{Surface $n$-gram.} A character $n$-gram classifier over the
context around an occurrence with every instance of the variable's name
replaced by a placeholder, fitted on the source language and applied to the
target. No model. We fix one masked-context variant in advance rather than taking the best per cell. The per-cell maximum is selected on the
evaluation fold, and every fixed variant gives a \emph{larger} boundary effect than it.
\item \textbf{Probe, span-pooled.} Logistic regression on residual activations
mean-pooled over the occurrence's own tokens, layer chosen on source-language
validation data. This reads the identifier.
\item \textbf{Probe, context-pooled.} The same, pooling the $16$ tokens either
side of the occurrence and \emph{excluding} its own. The forward pass is byte-identical, and only what is read changes. Masking the name in the source would
also change the input distribution.
\item \textbf{Untrained.} The same architecture and tokenizer with randomly
initialised weights, run at both poolings. A probe score means little without a
bound on what architecture and labels alone
supply~\citep{hewitt2019control,zhang2018language,belinkov2022probing}, and a
context-pooled probe must be read against a context-pooled floor: the two
poolings read different token sets, so their achievable scores differ for
reasons unrelated to training.
\end{itemize}

Models are Qwen2.5-Coder-1.5B~\citep{hui2024qwencoder} and, for the untrained
control, the architecture of the base model it is continued
from~\citep{qwen2024qwen25}. Confidence intervals resample whole problems, never
occurrences, since occurrences inside one program share a forward pass.

The $n$-gram baseline reaches $0.929$ between JavaScript and PHP without a model
and without seeing the variable's name, and loses $0.126$ on transfers to or
from Python: $95\%$ CI $[-0.160, -0.092]$, resampling the $427$ test problems.
The effect is not uniform across roles and is concentrated in
iterator, which alone gives $-0.225$ while accumulator and index\_key together
give $-0.059$. Iterator is also the role whose extractors agree least across the
boundary and whose intervals are twice as wide, so we treat the aggregate as an
upper bound on how much of this is about language rather than labelling.

\section{The probe looks invariant, and mostly should not}

Read against that, the span-pooled probe is remarkable: it moves $-0.012$, an
order of magnitude less, and clears an untrained network of the same
architecture by $+0.269$. That is the result the obvious reading calls
language-independent role representation.

\paragraph{It does not survive removing the identifier.} The probe pools over
the occurrence's own tokens, so the variable's name is inside what it reads,
while the baseline it is being compared against has that name masked. Pooling
only the surrounding tokens, with the forward pass unchanged, the probe falls
from $0.844$ to $0.589$ overall. Against its \emph{matched} untrained floor of
$0.496$ that is a margin of $+0.093$, against $+0.269$ before: $65\%$ of what
the probe knew came from the identifier.

\paragraph{So did the invariance.} The boundary effect grows from $-0.012$ to
$-0.061$, and the untrained network at the same pooling moves $-0.042$. With
the identifier removed the trained probe is no flatter than an untrained one.
The apparent language-independence was not a property of the role representation. It was a property of variable
names, which parallel implementations of the same problem tend to share.

\paragraph{What remains.} A margin of $+0.093$ over a matched floor is small but
consistent in both groups, so the model does encode something about roles beyond
the identifier. We do not claim it is language-independent: at that pooling its
boundary effect is indistinguishable from an untrained network's.

\section{Discussion}

The finding is methodological, and it generalises past this corpus. Any probe
that pools over a span containing an identifier can read that identifier, and
in parallel corpora identifiers are among the most language-invariant things
present. A cross-lingual probing result obtained that way will overstate
representational invariance by however much the naming happens to agree, and no
untrained-network control detects this: the untrained network reads the same
identifier and is defeated by the same confound. Only a comparator that cannot
see the name, or a pooling that excludes it, separates the two.

That is also why the model-free arm matters. The surface baseline is the thing
that made the asymmetry visible, because it was the only condition with the
identifier withheld. Prior cross-lingual probing of code
models~\citep{hernandezlopez2026syntactic,utpala2024language,kargaran2025programming}
has untrained-network floors but no model-free comparator, and would not surface
this. The concern generalises the standard caution that a probe reports what is
decodable rather than what the model
uses~\citep{belinkov2022probing,voita2020mdl}: here part of what is decodable is
the input itself, and it survives the control usually relied on.

\paragraph{Reconciling with prior alignment results.}
\citet{kargaran2025programming} find Python the \emph{least} aligned of these
three languages on parallel programs, which sits oddly beside a span-pooled
probe that barely moves across the Python boundary. The two measure different
things, whole-snippet retrieval against role decodability, and our
context-pooled result removes the tension: once the identifier is excluded, our
probe does show a boundary effect. What looked like disagreement was the
confound.

\paragraph{Limitations.} Three languages, of which one is the boundary, so the contrast has two points and no gradient, and Appendix~\ref{app:overlap}
shows XLCoST admits no wider version. One model at $1.5$B. The identifier-lift figures are
aggregated over three roles and we do not report them per role. Iterator's
labels come from a different extractor path than Python's, its minority class
falls to ten instances in some cells, and it carries most of the surface effect. The accumulator and index\_key
figures are the more trustworthy ones. Context
pooling excludes the identifier but not everything correlated with it, so
$+0.093$ is an upper bound on identifier-free role information. Finally, this is
a probing result: it says what is decodable, not what the model uses.

\section{Reproducibility}
\label{app:repro}
Every figure is regenerated from committed result files, and a regression test
recomputes each of them from those files rather than quoting them. Activation
extraction is the only step needing an accelerator. The probe is logistic
regression on activations mean-pooled over either the occurrence's span or the
$16$ tokens either side of it excluding the span; the surface baseline is a
\texttt{char\_wb} tf-idf vectoriser with $n \in [2,4]$ followed by logistic
regression, fitted on the source language only. Pooling and initialisation are
recorded in each store's identity, so a context-pooled store cannot be confused
with a span-pooled one downstream.
