\begin{abstract}
If language is a design axis rather than a passive carrier, then changing the
language should change what a model can do. We test this directly in code,
where the same problem can be written in several languages whose relatedness
is known independently. Fitting a variable-role classifier on one language and
evaluating it on another, we find that a model-free character $n$-gram
baseline is strongly constrained by language relatedness---macro-F1 $0.952$
between JavaScript and PHP, falling to $0.785$ whenever Python is
involved---while a linear probe on a code model's residual stream is nearly
unaffected by the same boundary, moving $0.006$. The probe is not reading the
input: an untrained network of identical architecture reaches $0.575$, and
both trained models clear it in all $18$ transfer cells. A model trained
\emph{without} code is equally invariant, so code pretraining is not the
cause. Examining why the surface fails, we find its discriminative $n$-grams
are not missing from the target ($70\%$ of weighted mass survives, $r=+0.09$
with transfer); they point the other way, and the share whose sign flips
predicts transfer almost exactly ($r=-0.98$). The medium therefore governs
surface generalisation and leaves the learned role representation largely
untouched---a dissociation that a purely behavioural evaluation would report
as a single number.
\end{abstract}

\section{Introduction}

The premise of treating language as a design axis is that the medium is not
neutral: rephrasing a problem changes what a model does with it. Programming
languages make this testable in a way natural languages rarely do. The same
algorithm can be written in Python, JavaScript, and PHP with the semantics
held fixed and the surface form varying along documented lines of descent, and
the resulting corpora can be aligned problem by problem. If the medium
constrains what a model represents, code is where that constraint should be
measurable rather than argued.

We ask a narrow version of the question. A \emph{variable role}---accumulator,
loop iterator, index key---is a property of what a variable does in a program,
not of what it is called or which language it appears in. Roles are therefore
a case where the medium ought, in principle, to be irrelevant. Whether it is
irrelevant \emph{to a model} is an empirical matter, and one that separates
two things a single accuracy number conflates: how far a surface regularity
carries across languages, and how far a learned representation does.

Our contribution is a controlled measurement of that separation, and a
mechanism for the part that fails. Fitting on one language and testing on
another over all six ordered pairs of Python, JavaScript, and PHP, a
model-free surface baseline tracks language relatedness closely while a
linear probe on the residual stream does not. We establish that this is a
property of the trained network rather than of our inputs by comparing against
an untrained network of identical architecture, and that it is not a property
of code pretraining specifically by comparing a code model against a non-code
model of the same family, scale, and tokenizer. Finally, we show that the
surface baseline fails for a reason that is not the obvious one: its features
are present in the target language and carry the opposite sign.

\section{Setup}

\paragraph{Corpus and alignment.} XLCoST~\citep{zhu2022xlcost} provides
parallel solutions to competitive-programming problems in several languages,
keyed by a problem identifier that is stable across languages. Every
comparison below is \emph{matched}: a classifier trained on language $A$ is
evaluated only on problems that also appear in $A$, so a drop in transfer
cannot be attributed to a change of subject matter. Matching is what makes the
medium the only thing varying, and it is also what restricts the study to
three languages. We computed the full pairwise overlap
(Appendix~\ref{app:overlap}): Python/JavaScript/PHP share $2{,}953$, $1{,}529$,
and $1{,}145$ problems, and \emph{no} other pair in XLCoST reaches $500$---
including same-family pairs such as C\# and Java, which share $175$. The
three-language limit is a property of the benchmark, not a choice.

\paragraph{Roles and occurrences.} We extract per-occurrence labels for
accumulator, iterator, and index\_key from language-specific parsers, cap each
role at $3{,}000$ occurrences sampled as whole problems, and use a frozen
hash-based split that assigns a problem to the same fold in every language.
Test folds hold $1{,}377$--$3{,}341$ occurrences, so one occurrence changing
its prediction moves macro-F1 by $\rho \in [0.0003, 0.0020]$; every effect we
report clears its own $\rho$ by at least an order of magnitude.

\paragraph{What is compared.} The \emph{surface baseline} is a character
$n$-gram classifier over the context around an occurrence with the variable's
own name masked, fitted on the source language and applied to the target; it
involves no model. The \emph{probe} is a logistic regression on residual-stream
activations at the occurrence, layer chosen on source-language validation
data. We report three models: Qwen2.5-Coder-1.5B, Qwen2.5-1.5B (the same
architecture, scale, and tokenizer trained without the code corpus), and an
untrained network with Qwen2.5-1.5B's architecture and randomly initialised
weights.

\section{The medium is encoded, and organised by lineage}
\label{sec:lineage}

Before asking whether the medium constrains role representations, it is worth
establishing that the model represents the medium at all. In prior work on
this corpus we applied PCA to last-token residual activations across $19{,}471$
XLCoST programs in seven languages. Language identity is linearly recoverable
from the embedding layer onward and peaks at layer $4$, where the first
principal component separates statically and dynamically typed languages
($r = +0.941$, $37\%$ of variance) and the scree plot shows a sharp elbow after
PC3. The sub-structure is what matters here: C and C++ occupy nearly the same
region, Java and C\# form an equally tight pair, and PHP sits apart from a
looser Python/JavaScript grouping. The arrangement recovers descent, not
merely a two-way typing split.

That result licenses the question this paper asks. The model does not treat
the language as incidental---it encodes it, early, and in a geometry that
mirrors how the languages are related. The rest of the paper asks whether that
encoded medium constrains what the model represents \emph{within} it.

\paragraph{The surface is constrained by the medium.} Between JavaScript and
PHP the $n$-gram baseline reaches $0.952$ with no model and without seeing the
variable's name. Across the Python boundary it loses $0.166$. The extreme cell
is iterator transferring from PHP to Python, which falls to $0.576$ against
$0.965$ from PHP to JavaScript---the same trained classifier, the same
problems, differing only in the language it is asked to read.

\paragraph{The representation is not.} The same split costs the code model's
probe $0.006$. Across all $18$ cells the surface baseline's spread is $0.390$
and the probe's is $0.107$: the surface measure varies $3.7\times$ as much.
The probe does not uniformly beat the baseline---it loses all six cells of the
closely related pair, where $n$-grams have already saturated---and this is the
point. The model contributes nothing where surface similarity is high and a
great deal where it is low.

\paragraph{Two controls decide what this means.} A flat curve is worthless if
the probe is reading the input rather than the model, and worthless again if
it is flat because it is uniformly poor. The untrained network settles both.
It reaches $0.575$ overall against $0.889$ and $0.892$ for the trained models,
a gap of $0.314$ present in \emph{all eighteen} cells with a minimum per-cell
lift of $0.126$; the probes are reading something the networks learned. It is
also itself flat, dropping $0.021$, which is exactly why flatness alone proves
nothing: a network that cannot separate the roles in any language is
trivially indifferent to which language it fails in. What distinguishes the
trained models is being flat \emph{and} high. The untrained network is not at
chance either---it clears its own shuffled-label control by $0.111$, as random
projections of token identity should---so $0.575$, not $0.5$, is the floor a
representational claim must clear.

\paragraph{Code pretraining is not the cause.} The non-code model of identical
architecture, scale, and tokenizer is equally invariant ($0.892$ against
$0.889$). Whatever makes the role representation insensitive to the medium is
not the code corpus.

\section{Why the surface fails, and why it is not syntax}
\label{sec:mechanism}

Calling the drop typological names it without explaining it. Because the
baseline fits its vectoriser on the source and only transforms the target, an
$n$-gram the target never produces contributes exactly zero, which makes the
mechanism measurable.

The obvious explanation is wrong. Weighting each feature by $|\beta_j|$ times
its mean tf-idf, roughly $70\%$ of the source classifier's discriminative mass
is realised in \emph{every} target, including the worst ($0.696$ for
php$\rightarrow$python against $0.735$ for php$\rightarrow$javascript), and
surviving mass does not predict transfer at all ($r = +0.09$ over the six
pairs). The cues are present.

What predicts transfer is whether they mean the same thing. Fitting a second
classifier on the target labels in the same feature space, the share of
target-realised mass whose sign flips between the two tracks transfer almost
exactly ($r = -0.98$): $5$--$7\%$ between JavaScript and PHP against
$18$--$37\%$ across the Python boundary, with no overlap between the groups.

The realignment is also distributed rather than localised, which rules out the
reading the word ``typological'' invites. Masking an entire syntactic
character class on both sides---terminators, braces, brackets, parentheses, or
operators---moves transfer by at most $0.021$ against a $0.39$ gap; masking
braces costs php$\rightarrow$javascript $0.001$. The difference is not carried
by block delimiters or statement terminators. We report the aggregate only:
the largest individual sign-flips are identifier and literal fragments, which
invites a story about naming idiom, but that story does not survive
checking---\texttt{i} carries the iterator label at $0.67$, $0.61$, and $0.64$
of its occurrences in PHP, JavaScript, and Python.

\section{Discussion}

Read against the design-axis premise, our results split it in two. The medium
demonstrably constrains surface generalisation: a strong lexical model loses a
sixth of its performance at a lineage boundary, and the model encodes that
same lineage geometrically (Section~\ref{sec:lineage}). But the medium leaves
the learned role representation nearly untouched, and it does so in a network
that never saw code. A behavioural evaluation reporting one cross-lingual
accuracy would average these into a single degraded number and attribute it to
the language, when the language is doing all of its work at the surface.

\paragraph{Limitations.} The matched triangle instantiates ``closely related''
by one pair and the boundary by one language; the axis is a two-point
contrast, not a gradient, and Appendix~\ref{app:overlap} shows XLCoST admits
no wider version. Both trained models are $1.5$B parameters from one family,
so nothing here speaks to scale. The mechanism analysis
(Section~\ref{sec:mechanism}) is run on the iterator role. The probe is
correlational: causal interventions on this corpus are reported in
Appendix~\ref{app:causal} but were not run on the cross-lingual cells. The
PCA result of Section~\ref{sec:lineage} is quoted from our prior submission
and, unlike every other figure here, is not regenerated by the released
pipeline.
